# Ενημέρωση, αναφορές και γέφυρες εταιρειών

## Εορτολόγιο

Στα Εργαλεία υπάρχει εορτολόγιο πελατών και συνεργατών. Διαβάζει την ονομαστική εορτή που έχει καταχωρηθεί σε κάθε καρτέλα, υπολογίζει την επόμενη ετήσια εμφάνισή της, επιτρέπει αναζήτηση και φίλτρα ημερομηνιών/τύπου προσώπου και ανοίγει την αντίστοιχη καρτέλα. Εμφανίζει και τις εγγραφές χωρίς συμπληρωμένη εορτή ώστε να διορθώνονται.

## Ενημέρωση

Η οθόνη βρίσκει ασφαλιστήρια με ημερομηνία λήξης στο επιλεγμένο διάστημα. Ο χρήστης φιλτράρει, επιλέγει παραλήπτες με checkboxes, συντάσσει SMS ή μορφοποιημένο email, βλέπει προεπισκόπηση και αποθηκεύει πρόχειρο. Υποστηρίζονται οι μεταβλητές `{όνομα}`, `{αριθμός}` και `{λήξη}`. Η αποστολή απαιτεί ρητή επιβεβαίωση.

Ο διαχειριστής καταχωρεί διεύθυνση/όνομα αποστολέα Brevo, όνομα αποστολέα Bulker και τα αντίστοιχα API keys από τις «Ρυθμίσεις αποστολής». Τα κλειδιά φυλάσσονται στο Windows Credential Manager του τρέχοντος χρήστη. Το Brevo χρησιμοποιεί transactional email API· το Bulker χρησιμοποιεί HTTP SMS API. Η εμφάνιση/αγορά SMS credits παραμένει ενημερωτική μέχρι να συνδεθεί η αντίστοιχη υπηρεσία λογαριασμού. Η επιτυχής απάντηση του API σημαίνει αποδοχή αιτήματος και όχι εγγυημένη παράδοση.

Τεκμηρίωση παρόχων: [Brevo transactional email](https://developers.brevo.com/reference/send-transac-email), [Bulker SMS HTTP και παράμετροι](https://www.bulker.gr/myschool-guide).

## Αναφορές

Διατίθενται σύνοψη, παραγωγή ασφαλιστηρίων, εκτίμηση αποδόσεων σε ασφαλιστικές, προμήθειες/αποδόσεις συνεργατών, υπόλοιπα πελατών, κινήσεις πελατών, ζημιές και οχήματα. Υπάρχουν φίλτρα αναζήτησης, εταιρείας, κλάδου, συνεργάτη και ημερομηνιών, καθώς και εξαγωγή CSV. Η απόδοση προς ασφαλιστική σημειώνεται ως εκτίμηση: η εφαρμογή δεν καταχωρεί ακόμη πραγματικές πληρωμές προς ασφαλιστικές, συνεπώς δεν μπορεί να υπολογίσει οριστικό ανεξόφλητο ποσό.

## Γέφυρες εταιρειών

Η οθόνη δείχνει αλφαβητικά προκαθορισμένες ασφαλιστικές και τα καταχωρημένα πρακτορεία/εταιρείες. Με κλικ ανοίγει επιλογή CSV. Το τυποποιημένο CSV απαιτεί `policy_number` και `customer_tax_number`. Προαιρετικές στήλες: `document_type` (`policy`, `application`, `notice`), `start_date`, `end_date`, `gross_premium`, `net_premium`, `branch` και, για πρακτορείο, `insurer`. Οι ημερομηνίες γράφονται `yyyy-MM-dd` ή `dd/MM/yyyy`. Η εισαγωγή επιβεβαιώνεται με προεπισκόπηση, συνδέεται με υπάρχον ΑΦΜ πελάτη, παραλείπει διπλότυπα και αναφέρει σφάλματα ανά γραμμή. Δεν δημιουργεί αυτόματα πελάτες.

Κάθε πρωτότυπο αρχείο ασφαλιστικής, καθώς και τιμολόγια, χρειάζεται δικό του μετατροπέα μετά τη λήψη πραγματικού δείγματος και αντιστοίχισης στηλών. Δεν γίνεται αυθαίρετη εισαγωγή άγνωστων αρχείων.
